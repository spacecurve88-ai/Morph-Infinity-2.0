# Delivery status and next work

The master prompt's phase numbering is primary; the technical plan uses a slightly different grouping.

## Phase 0 — baseline established, legacy evidence missing

Repository inspection established that no executable code, v8 source, tests, or real exported backups existed. Architecture, threats, format-2 fixtures, strict schema contracts, build tooling and test commands are now present. Legacy preservation/import acceptance remains blocked on a genuine fixture and original source. The original deployment remains untouched.

## Phase 1 — working vertical slice

Implemented named workspaces, empty reading/budget/blank collection proposals, approved typed field plans, editable records, computed AST formulas, persistent IndexedDB storage, sample previews, native JSON export, browser UI and deterministic tests. Plain-language parsing is a narrow, documented grammar. Unsupported requests cause no mutations.

## Phase 2 — foundational revision and recovery work

Implemented immutable full-state snapshots, parent-linked history, branch isolation, comparison, safe design-only/full-state restore, stale-tab conflicts, bounded validated native import, atomic pre-import recovery, raw corruption export and deliberate recovery restore. Automated merging, scalable history compaction, genuine legacy migration, and broader interruption/migration tests remain outstanding.

## Phase 3 — selected real behaviors

Implemented numeric sorting, text filtering across displayed values, table/cards, finite dimensional arithmetic, local-date capture on an actual status transition, idempotent capture, monthly date-count bars, typed fields and single-record relations with restrict deletion. Touch-sized controls and responsive workbench layout are present. Full release gates are not yet met: richer filter expressions, generalized conditional rules, timer behavior, boards, dashboards, undo/redo controls, multi-relation policies, broader aggregations, and physical iPad coverage remain.

## Phases 4 and 5 — deferred

No inference model, external provider, WebGPU benchmark, custom-code module or notification system has been added. These cannot authorize mutation and must not precede reliable core acceptance gates.

## Next highest-value work

1. Obtain a sanitized actual v8 backup and source; implement reversible migration against real fixtures, preserving unknown data rather than guessing nested schemas.
2. Run the browser suite on WebKit and a physical iPad; exercise storage failures, orientation, VoiceOver, offline reload and export/import.
3. Add history compaction and more recovery tests before increasing document limits.
4. Expand supported behaviors incrementally with typed contracts and end-to-end acceptance tests; add merge only with explicit conflict handling.
